# 港区档案 · 碧蓝航线120级科技清单

按**受益舰种＋加成属性**找到下一艘待练舰船。内置国服765艘科技舰船及本地头像，提供网格／表格、待练级／待觉醒／已完成／未拥有四种状态、批量标记、撤销、JSON备份。已同步2026年10月22日实装的长蛇号、雷伊尔·贝号、铁角号、水星号、塞利米耶号及其120级科技奖励。

## 在线使用

访问 [港区练级计划](https://syxupu.github.io/azur-lane-tech/)，无需安装或登录。程序和公开舰船资料由 GitHub Pages 提供，练级记录、科技目标、筛选与配色仅保存在访问者自己的浏览器，不发送到 GitHub 或其他服务器。

首次从本地版迁移：在原来的 `http://127.0.0.1:5173` 点击「导出备份」，到线上网站点击「导入备份」并核对预览。不同域名不能直接共享浏览器存档；备份迁移练级记录，科技目标和外观需在新地址重新设置。请固定使用同一网站地址，定期导出备份；清理浏览器数据或换设备后需要手动恢复。

## 本地启动

需要 Node.js 20 或更高版本、PowerShell 7。无需安装依赖。

双击 `启动工具.cmd`，或在此目录运行：

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File .\start.ps1
```

也可执行 `npm start`。工具会打开 **http://127.0.0.1:5173**，终端窗口保持运行，按 Ctrl+C 停止。若端口被占用会提示处理方法；不会擅自切换端口。不要直接双击 index.html。

## 使用

1. 首次全部为待练级。点击舰船卡片或表格整行选中，再次点击取消选择；可用空格或回车切换。选中后使用底部批量按钮标记；舰名仍打开百科，状态菜单独立操作。
2. 「我的科技目标」初始为空。点击「添加目标」，选择受益舰种和加成属性，添加后点击目标即可查看待练清单。每个目标右上角可删除，目标自动保存在当前浏览器，不会重复添加。
3. 清单上方可直接切换「全部／待练级／待觉醒／已完成／未拥有」。侧栏组合受益舰种、属性、自身舰种、阵营与稀有度；手机点击「筛选」打开面板。搜索支持原名、国服和谐名与编号。
4. 每艘船的状态菜单可单独修改。网格和表格统一按「待练级 → 待觉醒 → 未拥有 → 已达120级」排列，同一状态内按所选的图鉴编号、稀有度、名称或加成值排序，修改后立即调整位置。「全选筛选结果」会选择**所有页的当前筛选结果**，旁边显示准确数量。改变筛选会取消选择。每次修改和导入均可撤销一步。
5. 「全部科技加成」打开科技总览，选择受益舰种后查看各属性已获得／可获得上限；点属性卡片进入对应清单。
6. 顶栏齿轮打开「外观设置」。提供深海青、海盐蓝、鸢尾紫、樱花粉、松林绿、暖沙金六套配色，支持浅色、深色和跟随系统。自定义可用取色器或6位HEX编辑强调色、页面背景、卡片底色，明暗颜色分别保存；文字和状态色自动匹配，必要时调整显示颜色并说明，保留输入原色。修改即时生效，「恢复默认外观」回到深海青深色模式。

所有加成统计只计算120级奖励，不含获得奖励、阵营科技。目标统计使用该目标的完整名单，不随阵营、状态等清单筛选变化。多舰种奖励分别计算至各受益舰种，不把跨舰种数值累加成一个战力数值。

### 稀有度排序

首次访问且没有有效排序偏好时，默认使用「稀有度优先」。之后打开网站会恢复上次保存的排序方式；已有图鉴编号、名称或加成值排序偏好的用户不会被强制切换。

选择「稀有度优先」，在每个练级状态内按彩、金、紫、蓝、白降序排列。决战方案与海上传奇同档，最高方案与超稀有同档；同稀有度按游戏客户端配置编号升序，混排常规舰、方案舰和META舰，不按科技图鉴编号或舰名另分组。规则来自国服客户端 [ShipIndexCfg](https://github.com/AzurLaneTools/AzurLaneLuaScripts/blob/main/CN/view/ship/shipindexcfg.lua) 与 [ShipIndexConst.sortByCfg](https://github.com/AzurLaneTools/AzurLaneLuaScripts/blob/main/CN/model/const/shipindexconst.lua)。

本工具按单舰科技条目记录，使用未改造稀有度和客户端舰船组编号，不记录游戏内个体的改造、突破、等级或重复舰。游戏中改造后的稀有度与配置编号会改变，因此与实际船坞中已改造个体的位置可能不同。

### 待觉醒

「待觉醒」表示经验已足够升到120级，但尚未通过认知觉醒达到120级。可以在单舰状态菜单或底部批量操作中标记，使用对应标签单独查看；全局统计、科技目标、科技总览、科研候选统计及导入预览都会区分这一状态。它不计入已完成数量或已获得的120级科技，相关奖励单列为「待觉醒可得」。实际达到120级后，请再标记为「已达120级」。状态由用户手动记录，网站不会推断游戏内经验或觉醒进度。

### 科研练级联动

在「科研练级联动」选择正在解锁的科研船，支持一期至九期47艘。面板同时展示两段经验要求，点击「第一阶段／第二阶段」切换；网格和表格会用强调边框与「科研适用」文字高亮符合**当前阶段阵营＋舰船自身前后排类型**的候选船。勾选「只看符合科研条件的舰船」后，可与科技目标、状态、搜索等筛选组合；面板统计区分全名单可用数与当前筛选可用数。

两段条件分别保存：马可·波罗第一段铁血／撒丁主力、第二段皇家／撒丁主力；契卡洛夫第一段撒丁／北联主力、第二段白鹰／北联主力；瓦尔帕莱索第一段皇家主力、第二段白鹰主力。吾妻、埃吉尔、布雷斯特第一段需要主力、第二段需要先锋。其他跨阵营任务也使用任务表中的完整条件，不用科研船自身阵营推断。

META不属于原阵营，潜艇也不计入先锋或主力任务。东煌任务可选择四艘导驱的当前模式：默认按未改造／先锋模式计算，切换为主力模式会从先锋候选中排除；此设置统一应用于四艘导驱。μ兵装、小船按自身阵营与舰种匹配。已达120级的舰船仍能刷科研经验，保留高亮；未拥有船需先获得，正在解锁的科研船自身不列为候选。本清单仍只覆盖具有120级科技奖励的舰船，不是完整游戏船坞。

选择的科研船、阶段、候选筛选及导驱模式存于原偏好键的新增 `research` 字段，旧设置自动默认为关闭。未改变练级记录、外观存档或v1备份格式；科研选择不包含在练级备份中。点击「关闭联动」可恢复普通清单；此功能不读取游戏进度、不记录经验完成量，也不自动将两阶段标记完成。经验获取场合等规则参见 [BWIKI「开发船坞」](https://wiki.biligame.com/blhx/开发船坞#科研经验相关)。

修改状态、批量标记与撤销时，网格卡片和表格行会平滑移动到新的排序位置；离开当前筛选或分页的舰船短暂淡出。动画不延迟存档，连续修改会从当前位置衔接；系统开启「减少动态效果」时直接显示最终位置。

维护者验证动效：本地启动后访问 `http://127.0.0.1:5173/tests/list-motion.browser.html`，点击「运行检查」。检查使用浏览器真实动画引擎验证移动轨迹、连续修改、淡出清理及减少动态效果；可在桌面和手机宽度分别运行，不读取用户存档，测试页不随网站发布。

## 保存与备份

进度和界面设置（包括自定义科技目标）保存在当前浏览器、当前来源的 `localStorage`。线上版固定使用上述HTTPS地址，本地版固定使用 `http://127.0.0.1:5173`；改成 localhost、换域名、换浏览器或清理浏览器数据，均无法直接读取原来的记录。JSON备份用于迁移练级记录，界面设置仍由各浏览器独立保存。

外观单独保存在 `azur-tech:appearance:v1`，不改变舰船记录或科技目标，也不包含在练级JSON备份中。恢复默认外观只重置配色和显示模式；保存失败会明确提示，当前页面仍可继续预览。

请定期点击「导出备份」。换电脑或换浏览器后，打开工具并导入JSON，先核对预览再应用。导入替换当前记录，未知舰船ID仍保留；名单缺少的舰船默认待练级。存储受限时页面显示警告，当次修改仍可导出。

待觉醒记录也会随备份保存。为兼容既有v1记录，存储键和备份版本不变：JSON的 `statuses` 将待觉醒写为 `pending`，并用可选的 `awakening` 舰船ID数组补充精确状态，新版本读取时恢复为待觉醒；无待觉醒记录时不写此数组。旧备份可直接导入。若需回退旧版代码，请先导出并保留原备份：旧版仍可读取其他进度，会将待觉醒显示为待练级；以后在新版导入同一原备份可无损恢复。旧版重新保存或导出的记录不包含待觉醒标记，不应替代保留的原备份。

本地版的静态文件和头像全部在本地，安装好运行环境后断开外网也可启动和使用；线上版加载页面和素材需要联网。舰船详情外链及更新数据需要联网。工具不读取游戏账号、游戏客户端或实际等级。

## 发布与更新网站

源代码位于 [syxupu/azur-lane-tech](https://github.com/syxupu/azur-lane-tech) 的 `main` 分支；GitHub Pages 从 `gh-pages` 分支根目录发布。发布分支仅含页面运行文件、舰船资料和引用素材，不包含本地截图、设计文档、测试、备份或环境文件。

维护者修改后，先将源代码提交并推送至 `main`，再在本项目目录运行：

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File .\scripts\publish-pages.ps1
```

需 Node.js、Git、PowerShell 7，以及已通过 `gh auth login` 登录且具有仓库写权限的 GitHub CLI。脚本运行测试、生成 `dist/`、使用临时检出提交并推送 `gh-pages`；不强推，不切换当前工作分支。GitHub Pages 随后自动部署。只构建可用 `npm run build:pages`；仅推送 `main` 不更新线上版本。

发布更新不改写访问者的浏览器存档；名单新增时仍沿用既有ID匹配和默认待练逻辑。发布方式依据 [GitHub Pages 分支发布文档](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## 数据来源与更新

来自[碧蓝航线 BWIKI「舰队科技」](https://wiki.biligame.com/blhx/舰队科技)。快照时间显示在页面底部；来源修订号保存在 `data/ships.json`。头像及角色素材版权归原权利人，来源URL保留在数据中，本项目为非官方个人养成工具。

舰种图标使用BWIKI舰船详情中的原始 `ShipType-*.png` 游戏素材，15张透明PNG覆盖18个舰种名称。来源、尺寸与校验值保存在 `assets/hulls/manifest.json`；风帆S/V/M沿用来源中的通用风帆图标。卡片、表格、自定义目标和目标统计均使用本地图标；缺失时仍有文字标签。维护者可运行 `node scripts/update-hull-icons.mjs` 更新素材。

```powershell
npm run update-data
npm run update-game-rules
npm test
```

更新脚本解析「120级」奖励列和对应筛选字段，按科技图鉴编号存储，下载缺少的头像。验证完整性后再替换快照，来源不可用、结构变化或条目不足时保留旧数据；头像下载失败时仍保留舰船并由页面显示舰名占位，下次更新会重试。支持 `node scripts/update-data.mjs --source <本地HTML>` 从已保存页面更新。

更新后刷新页面：原有状态保留，新增编号设为待练级，并显示新增数量；暂时离开名单的旧状态继续保留在备份中。改造形态共用同一科技条目；具有独立编号的META、II型等分别记录。列表只涵盖来源科技表，不包含没有120级科技奖励的舰船。

## 维护与验证

`data/game-rules.json` 独立保存舰船组编号、阵营、舰种及每艘科研船两段经验任务的阵营／舰种组合。来源为 AzurLaneTools 的国服客户端提取表，`sourceRevision` 记录同一次下载的Git提交，界面不依赖第三方实时请求。运行 `npm run update-game-rules` 会先解析并验证全部条目及两段任务，再替换快照；基础舰船名单更新后也需运行此命令。它不修改 `data/ships.json` 或用户记录。维护脚本支持 `--source-dir <Lua目录> --revision <来源提交SHA>` 离线解析已保存的四张表。

新增回归检查覆盖47艘科研船、94段任务、稀有度同档混排、状态分组优先、跨阵营／跨前后排切换、导驱模式、META与潜艇排除、科技筛选交集及旧偏好回退。新增运行文件已纳入Pages发布白名单。

纯 HTML / CSS / 原生 JavaScript，无运行时第三方依赖，使用系统中文字体。`core.js` 提供筛选、统计、状态合并与备份校验的纯函数，`app.js` 负责界面和持久化，`ui-icons.js` 提供本地 SVG 图标，`scripts/` 提供本地服务与数据更新。

`theme.js` 生成明暗语义颜色及可读性约束；`appearance.js` 管理外观面板和独立存储；`appearance-boot.js` 在页面首屏绘制前应用验证后的本地颜色缓存，减少刷新时颜色闪烁。`settings.css` 提供响应式设置面板。

界面规范记录在 `design-system/harbor-archive/MASTER.md`。2026-10-24 重构保留原存档和备份格式；手机表格改为纵向条目，筛选使用原生对话框，控件提供可见键盘焦点与至少44px的主要点击区域。

`npm test` 使用 Node 内置测试运行器，覆盖数据完整性、全部本地头像、常见科技组合、别名、多舰种奖励、科研与META、筛选排序、全完成／未拥有、备份往返、名单更新及错误输入；另覆盖自定义目标验证/去重/删除、全部舰种图标的路径/PNG尺寸/校验值、12种预设外观与极端自定义颜色的对比度、损坏设置回退和系统模式。来源更新可能改变目标数量，需核对新增舰船后更新对应快照断言。
